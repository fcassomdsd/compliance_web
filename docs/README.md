# Project Documentation Index

This directory is the source of truth for `compliance_web` documentation. It is organised by the current state of the code, not by a delivery phase. Superseded point-in-time artifacts (delivery summaries, lint snapshots) live under `docs/archive/` and are kept for history only.

## Structure

### Authentication (`docs/auth/`)

- `AUTH_CHUNK1_API_SPEC.md` — endpoint contract for the auth/session API.
- `AUTH_CHUNK1_ROUTE_AUTH_MATRIX.md` — route → required-role matrix.
- `ALFRESCO_ROLE_SETUP.md` — walkthrough for mapping Alfresco groups to app roles.
- `AUTH_CHUNK8_OPERATIONAL_READINESS.md` — pre-merge CI gate and outage/rollback runbook for auth changes.

### Checklist Manager (`docs/checklist/`)

- `CHECKLIST_MODULE_DOCS.md` — how the Checklist Manager works (the two Pinia stores, save semantics, specialty scoping).
- `CHECKLIST_DEVELOPER_GUIDE.md` — developer-oriented walkthrough of the module.
- `CHECKLIST_QUICK_START.md` — quick start for the module.

### Shared operations (`docs/shared/operations/`)

- `DOCKER_SETUP.md` — container/network setup for the service.
- `GITLAB_CI.md` — CI pipeline reference.

### Other references

- `STYLE_GUIDE.md` — UI conventions, status machine table (§12), and cross-cutting rules.
- `endpoints.md` — the complete server HTTP endpoint surface, generated by `scripts/verify-endpoints.mjs` from the Express routers (do not edit by hand).
- `archive/` — superseded point-in-time documents (checklist delivery handoff, a historical lint report).

## Server module documentation

`server/README.md` documents the backend module directly; its endpoint list has been replaced by `docs/endpoints.md`, the authoritative, machine-checked manifest. `migrations/` holds the database schema (SQL) and is applied with `npm run db:migrate`.
